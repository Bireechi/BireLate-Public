What the answers mean

No content script in this tab — Firefox is not running this extension on that page at all. Reload the tab and try again; a tab that was already open before the extension was loaded never gets it.

Frames that answered — one card follows per frame. A reader drawn inside an iframe reports as its own frame, with its own host.

Enabled here: no — the page is switched off, and Why names the host that was checked. If that host is not the one you ticked on the Home tab, the reader is coming from a different site than the address bar; turn on Enable on every page in Settings.

Show a button: 0 with a large Rejected: too small — lower Minimum image detection size in Settings.

Ready to translate: 0 while images show a button — the browser only holds a tiny stand-in for each page. This reader lazy-loads: scroll each page into view and the count rises. lazy: data-src=… under an image below says the same thing, and its natural size next to a much larger rendered size is the proof.

Responsive (srcset / picture) — those images pick their own file from a list. They are translated by silencing that list first; if a translation ever appears to do nothing on such an image, say so with this number.

covered by … on an image — something is painted on top of it to deter saving. That is fine: the button finds images by position, not by what the mouse lands on.

Big <canvas> or CSS background panels above zero with no usable images — the reader does not use <img> at all, and this extension cannot translate it.

Overlay in the DOM: not built yet is normal. It is created the first time you hover an image.
